# Firestore 프로필 기반 플레이어 네트워크 데이터 연동

**날짜:** 2026-05-06  
**관련 파일:**
- `Assets/Scripts/Core/AuthManager.cs`
- `Assets/Scripts/Core/Data/User/UserData.cs`
- `Assets/Scripts/Core/Data/User/UserDataService.cs`
- `Assets/Scripts/Core/Data/Network/PlayerNetworkData.cs`
- `Assets/Scripts/Player/PlayerController.cs`

---

## 작업 배경

기존에는 플레이어가 네트워크에 스폰된 뒤 Firebase Auth의 UID만 서버로 전달하고, 플레이어 닉네임과 색상은 UID를 기준으로 임시 생성했다.

하지만 `UserDataService`에서 이미 Firestore의 `users/{uid}` 문서에 `Nickname`, `ColorHex`를 저장하고 있으므로, 네트워크 플레이어 데이터도 이 실제 프로필 데이터를 기준으로 동기화하도록 변경했다.

---

## 데이터 흐름

현재 플레이어 프로필 데이터 흐름은 아래 순서로 진행된다.

1. `FirebaseManager`가 Firebase 초기화를 완료한다.
2. `AuthManager`가 Firebase Auth 익명 로그인을 진행한다.
3. 로그인된 UID를 기준으로 `UserDataService.GetUserDataAsync(uid)`를 호출한다.
4. Firestore `users/{uid}` 문서가 있으면 기존 데이터를 로드한다.
5. 문서가 없으면 기본 `Nickname`, `ColorHex`를 생성해 Firestore에 저장한다.
6. `AuthManager.CurrentUserData`에 로드된 `UserData`를 보관한다.
7. `PlayerController`의 오너 클라이언트가 `CurrentUserData` 로드를 기다린다.
8. `Uid`, `Nickname`, `ColorHex`를 `PlayerNetworkData`에 채운 뒤 서버 RPC로 전달한다.
9. 서버가 `NetworkVariable<PlayerNetworkData>`에 값을 저장한다.
10. 모든 클라이언트가 `PlayerData.OnValueChanged`를 통해 플레이어 비주얼을 갱신한다.

## 추가된 네트워크 데이터 구조

`PlayerNetworkData` 구조체를 추가했다.

```csharp
public struct PlayerNetworkData : INetworkSerializable
{
    public FixedString64Bytes Uid;
    public FixedString64Bytes Nickname;
    public FixedString64Bytes ColorHex;

    public void NetworkSerialize<T>(BufferSerializer<T> serializer) where T : IReaderWriter
    {
        serializer.SerializeValue(ref Uid);
        serializer.SerializeValue(ref Nickname);
        serializer.SerializeValue(ref ColorHex);
    }
}
```

Netcode의 `NetworkVariable<T>`에 넣어 동기화해야 하므로 `INetworkSerializable`을 구현했다. 문자열은 일반 `string` 대신 Netcode 직렬화에 적합한 `FixedString64Bytes`를 사용했다.

## PlayerController 변경 사항

기존에는 UID만 서버로 보냈다.

```csharp
RegisterUidServerRpc(AuthManager.Instance.UserId);
```

변경 후에는 `AuthManager.CurrentUserData`를 기다린 뒤 Firestore 프로필 값을 `PlayerNetworkData`로 구성해 서버로 보낸다.

```csharp
UserData userData = AuthManager.Instance.CurrentUserData;
PlayerNetworkData playerData = new PlayerNetworkData
{
    Uid = string.IsNullOrEmpty(userData.Uid) ? AuthManager.Instance.UserId : userData.Uid,
    Nickname = string.IsNullOrEmpty(userData.Nickname) ? "Player" : userData.Nickname,
    ColorHex = string.IsNullOrEmpty(userData.ColorHex) ? "#FFFFFF" : userData.ColorHex
};

RegisterPlayerDataServerRpc(playerData);
```

서버 RPC는 구조체 전체를 받아 `PlayerData`에 저장한다.

```csharp
[ServerRpc]
private void RegisterPlayerDataServerRpc(PlayerNetworkData playerData)
{
    PlayerData.Value = playerData;
}
```

## 플레이어 비주얼 적용 방식

기존에는 UID에서 임시 닉네임과 색상을 생성했다.

- `CreateNicknameFromUid`
- `CreateColorFromUid`
- `CreateStableHash`

위 임시 로직은 제거했다.

현재는 `PlayerData.Nickname`, `PlayerData.ColorHex`를 사용한다. 색상은 Unity 기본 API인 `ColorUtility.TryParseHtmlString`으로 변환한다.

```csharp
private bool TryCreateColorFromHex(string colorHex, out Color color)
{
    if (string.IsNullOrEmpty(colorHex))
    {
        color = default;
        return false;
    }

    return ColorUtility.TryParseHtmlString(colorHex, out color);
}
```

Firestore에는 `#RRGGBB` 형태의 문자열을 저장하고, 클라이언트에서는 이를 Unity `Color`로 변환해 렌더러에 적용한다.

## MPPM 테스트 이슈

MPPM으로 여러 인스턴스를 실행했을 때 Firestore 유저 문서가 1개만 생성되는 현상이 있었다.

원인은 Firestore 문서 생성 로직이 아니라 Firebase Auth의 기존 익명 유저 재사용 로직이었다.

```csharp
if (currentUser != null && currentUser.IsValid())
{
    UserId = currentUser.UserId;
}
else
{
    var result = await auth.SignInAnonymouslyAsync();
}
```

Firebase Auth는 이미 로그인된 익명 유저가 있으면 같은 UID를 계속 재사용한다. 따라서 여러 테스트 인스턴스가 같은 Auth 세션을 공유하면 모두 같은 `users/{uid}` 문서를 조회하게 되고, 결과적으로 Firestore 문서가 1개만 보일 수 있다.

## AddUserTest 옵션

MPPM 테스트 편의를 위해 `AuthManager`에 테스트용 옵션을 추가했다.

```csharp
[Header("Test")]
[SerializeField] private bool AddUserTest;
```

`AddUserTest`가 켜져 있고 기존 로그인 유저가 있으면, 기존 세션을 로그아웃하고 새 익명 로그인 흐름을 타도록 처리한다.

```csharp
if (AddUserTest && currentUser != null)
{
    auth.SignOut();
    currentUser = null;
    UserId = null;
    CurrentUserData = null;
    Debug.Log("[Auth] AddUserTest enabled. Signed out existing user.");
}
```

이 옵션은 개발 및 MPPM 테스트 전용이다. 실제 서비스에서는 기존 익명 유저를 재사용해야 앱을 다시 실행해도 같은 유저 프로필을 유지할 수 있다.

## 현재 상태

- Firestore 유저 프로필 데이터가 네트워크 플레이어 데이터로 전달된다.
- `PlayerNetworkData`는 `Uid`, `Nickname`, `ColorHex`를 포함한다.
- `PlayerController`는 UID 기반 임시 생성 대신 Firestore 프로필 값을 사용한다.
- `ColorHex`는 Unity `ColorUtility`로 파싱해 플레이어 색상에 적용한다.
- MPPM 테스트용으로 `AddUserTest` 옵션을 켜면 새 익명 유저 생성을 유도할 수 있다.

---

## 검증 방법

1. `FirebaseManager`와 `AuthManager`가 씬에 존재하는지 확인한다.
2. MPPM 각 인스턴스에서 필요 시 `AuthManager.AddUserTest`를 활성화한다.
3. Host와 Client를 실행한다.
4. 콘솔에서 아래 로그 흐름을 확인한다.

```text
[Auth] Firebase Authentication initialized.
[Auth] New Anonymous Login / UID: ...
[Firestore] LoadOrCreate Start
[Auth] UserData Loaded / Nickname: ..., ColorHex: ...
[PlayerController] Registered PlayerData: ..., ..., ...
[PlayerController] PlayerData Synced: ..., ..., ...
```

5. Firestore `users` 컬렉션에 UID별 문서가 생성되는지 확인한다.
6. 각 플레이어의 렌더러 색상이 `ColorHex` 기준으로 적용되는지 확인한다.

---

## 주의 사항

`AddUserTest`를 켜면 실행할 때마다 새 익명 유저가 생성될 수 있다. Firebase Auth와 Firestore에 테스트 데이터가 계속 쌓일 수 있으므로, 테스트가 끝난 뒤에는 옵션을 끄거나 테스트 데이터를 정리해야 한다.
