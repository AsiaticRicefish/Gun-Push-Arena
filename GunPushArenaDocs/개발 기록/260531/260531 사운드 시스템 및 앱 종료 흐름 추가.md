# 사운드 시스템 및 앱 종료 흐름 추가

**날짜:** 2026-05-31  
**작업 기간:** 2026-05-31  

## 작업 요약

오늘 작업에서는 `Gun Push Arena`의 MVP 구조를 크게 흔들지 않고, 전역 사운드 관리 구조와 주요 게임 이벤트 사운드 호출 흐름을 추가했다.

기존 방향은 그대로 유지했다.

```text
Firestore
-> 로비/방/최종 맵/Relay JoinCode 공유

Relay + Netcode
-> 실제 게임 중 이동, 발사, 충돌, 피격, 승패 처리

Audio
-> 각 클라이언트 로컬 재생 또는 서버 확정 후 ClientRpc 재생
```

이번 작업의 핵심은 다음과 같다.

```text
AudioData
-> 사운드 ID와 AudioClip 설정 관리

AudioManager
-> BGM/SFX 재생, 볼륨, on/off 관리

PlayerController
-> 서버 권한 이벤트 확정 후 전투 SFX ClientRpc 재생

Lobby / Result UI
-> 로컬 UI/결과 사운드 재생

ApplicationQuitter
-> LoginScene / LobbyScene 종료 버튼 공통 처리
```

## AudioData 구조

처음에는 사운드별로 `AudioClip` 필드를 직접 나열하는 방식도 고려했다.

```text
LobbyBgm
GameBgm
Jump
Fire
Hit
...
```

하지만 이 방식은 사운드가 늘어날수록 `AudioManager`에 `PlayJump`, `PlayFire`, `PlayHit` 같은 메서드가 계속 늘어나는 문제가 있었다.

따라서 최종적으로는 다음 구조를 사용했다.

```text
SoundId enum
SoundEntry
AudioData ScriptableObject
```

`SoundId`는 코드에서 사운드를 안전하게 식별하기 위한 enum이다.

```text
LobbyBgm
GameBgm
UiConfirm
MapGenerateSuccess
MapGenerateFail
GameStart
Jump
Fire
Hit
Fall
Respawn
Win
Lose
```

`SoundEntry`는 사운드 하나의 Inspector 설정 단위다.

```text
Id
Clip
Volume
Loop
```

`AudioData`는 Inspector에서는 `List<SoundEntry>`로 편집하고, 런타임에서는 내부 `Dictionary<SoundId, SoundEntry>` 캐시로 조회한다.

이 구조를 선택한 이유는 다음과 같다.

```text
Unity 기본 Inspector에서 관리하기 쉬움
Dictionary를 직접 직렬화하지 않아도 됨
AudioManager 코드가 사운드 종류에 덜 의존함
사운드별 볼륨 설정을 Inspector에서 조절 가능
Addressables 없이 단순하게 유지 가능
```

현재 프로젝트는 출시 목적의 대형 프로젝트가 아니라 개인 실험 프로젝트이므로 Addressables, AudioMixer, 동적 로딩, 복잡한 사운드 풀링은 제외했다.

## AudioManager 구조

`AudioManager`는 기존 `GlobalSingleton<T>`를 상속한다.

따라서 한 번 생성되면 `DontDestroyOnLoad`로 씬 전환 후에도 유지된다.

주요 역할은 다음과 같다.

```text
BGM AudioSource 관리
SFX AudioSource 관리
BGM on/off
SFX on/off
BGM 전체 볼륨
SFX 전체 볼륨
SoundEntry 개별 볼륨 반영
같은 BGM 중복 재시작 방지
비어 있는 AudioData / Clip 조용히 무시
```

현재 주요 메서드는 다음과 같다.

```text
PlayBgm(SoundId soundId)
StopBgm()
PlaySfx(SoundId soundId)
```

BGM은 반복 재생을 기준으로 하고, SFX는 `PlayOneShot`을 사용한다.

```text
BGM
-> AudioSource.clip 교체
-> loop = true
-> Play

SFX
-> PlayOneShot
```

`AudioSource`가 Inspector에 연결되어 있지 않아도 실행 시 자동으로 추가하도록 했다.

## AudioManager 배치 기준

현재 추천 배치는 `LoginScene`에 `AudioManager` 오브젝트를 하나만 두는 방식이다.

```text
LoginScene
└── AudioManager
    ├── AudioManager 컴포넌트
    └── AudioData asset 연결
```

이유는 로그인 씬이 앱의 첫 진입 지점이고, `AudioManager`가 `DontDestroyOnLoad`로 유지되기 때문이다.

예상 흐름은 다음과 같다.

```text
LoginScene
-> AudioManager 생성
-> LobbyScene 진입
-> LobbyBgm 재생
-> Map1 진입
-> GameBgm 재생
-> 결과 후 LobbyScene 복귀
-> LobbyBgm 재생
```

`LobbyScene`과 `Map1`에 `AudioManager`를 중복 배치할 필요는 없다.

## BGM 연결

### LobbyScene

`LobbyUIController.Start()`에서 로비 BGM을 재생한다.

```text
LobbyUIController.Start
-> AudioManager.Instance.PlayBgm(SoundId.LobbyBgm)
```

로비 씬은 방 생성, 참가, 맵 생성 대기 시간이 있으므로 BGM이 가장 자연스럽게 필요한 구간이다.

### Map1

`GameSceneBootstrap.Start()`에서 게임 BGM을 재생한다.

```text
GameSceneBootstrap.Start
-> AudioManager.Instance.PlayBgm(SoundId.GameBgm)
-> LoadRoomMapAsync
```

게임 씬 진입 시 BGM이 먼저 교체되고, 이후 Firestore FinalMap 로드와 맵/플레이어 스폰 흐름이 진행된다.

## 로비 SFX 연결

`LobbyPresenter`에서 맵 생성 결과와 게임 시작 사운드를 로컬 재생하도록 연결했다.

맵 생성 결과:

```text
HandleGenerateMapAsync
-> roomMapService.GenerateAndSaveMapAsync
-> 성공이면 MapGenerateSuccess
-> 실패이면 MapGenerateFail
```

게임 시작:

```text
HandleStartGameAsync
-> Starting game 상태 진입 시 GameStart 로컬 재생
-> Relay Host 시작
-> relayJoinCode 저장
-> room status Starting
```

이 사운드들은 네트워크 권한 이벤트가 아니라 로비 UI 흐름이므로 `ClientRpc`를 사용하지 않는다.

## 전투 SFX 연결

게임 중 전투 사운드는 서버에서 실제 이벤트가 확정된 뒤 `ClientRpc`로 모든 클라이언트에게 한 번씩 재생한다.

이 기준을 사용한 이유는 다음과 같다.

```text
입력 순간 로컬 재생과 서버 확정 재생이 중복되는 문제 방지
쿨다운 실패, 무적 상태, Lives 0 같은 무효 이벤트에서 사운드가 나는 문제 방지
Netcode 서버 권한 구조 유지
```

`PlayerController`에 공통 `ClientRpc`를 추가했다.

```text
PlaySoundClientRpc(SoundId soundId)
-> AudioManager.Instance.PlaySfx(soundId)
```

### 점프

`FixedUpdate()`에서 서버가 실제 점프를 적용하는 순간 재생한다.

```text
serverJumpRequested == true
remainingJumpCount > 0
-> velocity.y = jumpForce
-> remainingJumpCount--
-> Jump SFX ClientRpc
```

### 발사

`FireServerRpc()`에서 쿨다운, Lives, projectilePrefab 검사를 통과하고 투사체를 Spawn한 뒤 재생한다.

```text
FireServerRpc
-> cooldown 통과
-> projectile Spawn
-> NetworkProjectile.Initialize
-> Fire SFX ClientRpc
```

### 낙사

`HandleFallOut()`에서 서버가 Lives를 감소시키는 시점에 재생한다.

```text
position.y < deathY
-> Lives 감소
-> Fall SFX ClientRpc
```

### 리스폰

`Respawn()`에서 서버가 위치를 리스폰 지점으로 되돌리고 무적을 시작한 뒤 재생한다.

```text
Respawn
-> velocity 초기화
-> respawnPosition 이동
-> BeginInvulnerability
-> Respawn SFX ClientRpc
```

### 피격 / 넉백

`NetworkProjectile`을 직접 수정하지 않고, `PlayerController.ApplyProjectileHit()` 안에서 처리했다.

```text
NetworkProjectile.OnTriggerEnter2D
-> hitPlayer.ApplyProjectileHit(direction)
-> true 반환 시에만 실제 피격 확정
-> ApplyProjectileHit 내부에서 Hit SFX ClientRpc
```

이렇게 하면 다음 상황에서는 피격음이 나지 않는다.

```text
자기 투사체 충돌 무시
무적 상태
Lives 0
서버가 아닌 클라이언트 측 충돌
```

## 결과 SFX 연결

`GameResultPresenter.Show()`에서 각 클라이언트가 자기 결과에 따라 로컬로 승리/패배 사운드를 재생한다.

```text
winnerClientId == LocalClientId
-> view.ShowWin
-> Win SFX

winnerClientId != LocalClientId
-> view.ShowLose
-> Lose SFX
```

결과 사운드는 이미 `AnnounceGameResultClientRpc`를 통해 각 클라이언트에서 결과 표시가 실행된 뒤 판단할 수 있으므로, 별도 사운드 RPC를 추가하지 않았다.

## 앱 종료 버튼 흐름

로그인 화면과 로비 화면에 종료 버튼을 둘 수 있도록 공통 종료 유틸을 추가했다.

```text
ApplicationQuitter.Quit()
```

동작은 다음과 같다.

```text
Unity Editor
-> EditorApplication.isPlaying = false

Build
-> Application.Quit()
```

연결 메서드는 다음과 같다.

```text
LoginUIController.OnClickQuitGame
LobbyUIController.OnClickQuitGame
```

Unity Editor에서는 LoginScene / LobbyScene의 종료 버튼 OnClick에 각각 해당 메서드를 연결하면 된다.

## 배경 이미지 배치 메모

오늘 테스트 중 게임 씬 배경 이미지를 `Canvas` 안에 배치하면 월드에 생성된 맵이 가려지는 문제가 확인되었다.

원인은 `Canvas`가 `Screen Space - Overlay`일 때 UI Image가 카메라 월드보다 위에 그려지기 때문이다.

게임 씬 배경은 UI가 아니라 월드 배경으로 배치하는 것이 좋다.

권장 구조는 다음과 같다.

```text
Map1
├── Main Camera
├── Background
│   └── SpriteRenderer
├── Canvas
│   └── GameResultPanel
├── GameMapSpawner
├── NetworkPlayerSpawner
└── GameRoundManager
```

추천 설정:

```text
Background
-> SpriteRenderer
-> Sorting Layer: Background
-> Order in Layer: -100
-> Z 위치는 카메라와 맵보다 뒤쪽
```

맵/플레이어/투사체는 배경보다 높은 Sorting Layer 또는 Order를 사용한다.

```text
Map/Floor/Wall
-> Default 또는 Map
-> Order 0 이상

Player
-> Player
-> Order 10 이상

Projectile
-> Projectile
-> Order 20 이상
```

로그인 화면 배경은 UI 위주의 화면이므로 Canvas 안의 Image로 두어도 괜찮지만, 게임 씬 배경은 SpriteRenderer로 월드에 두는 편이 안전하다.

## Unity Editor 오류 메모

작업 중 다음 Editor 오류가 확인되었다.

```text
SerializedObjectNotCreatableException: Object at index 0 is null
UnityEditor.GameObjectInspector.OnEnable
UnityEditor.TransformInspector.OnEnable
```

이 오류는 현재 스택에 프로젝트 스크립트가 포함되어 있지 않았고, 게임 실행 자체에는 문제가 없었다.

의미는 대체로 다음에 가깝다.

```text
Inspector가 이미 Destroy되었거나 null이 된 오브젝트를 그리려고 함
```

발생 가능 상황:

```text
Play Mode 중 선택한 오브젝트가 씬 전환으로 사라짐
DontDestroyOnLoad 오브젝트와 씬 오브젝트가 바뀌는 순간 Inspector 대상이 null이 됨
Inspector Lock 상태에서 사라진 오브젝트를 계속 보고 있음
EditorApplication.isPlaying = false로 Play Mode 종료 시 선택 대상이 사라짐
```

게임 실행에 문제가 없고, 스택에 프로젝트 코드가 없다면 우선 큰 수정 없이 관찰하면 된다.

대응 방법:

```text
Inspector Lock 해제
Hierarchy에서 살아 있는 다른 오브젝트 선택
Console Clear
Editor 재시작
```

결과:

남아 있는 경고는 기존 `OllamaAiMapClient.OllamaGenerateResponse` 직렬화용 필드 경고다.

```text
OllamaGenerateResponse.response 필드에는 할당되지 않으므로 항상 null 기본값을 사용합니다.
```

해당 필드는 Unity `JsonUtility` 역직렬화용 필드이므로 현재 동작에는 영향이 없다.

## 정리

오늘 작업으로 `Gun Push Arena`에 사운드 시스템의 기본 골격이 들어갔다.

`AudioData`는 사운드 설정을 관리하고, `AudioManager`는 재생을 담당한다. 전투 중 핵심 효과음은 Netcode 서버 권한 이벤트가 확정된 뒤 `ClientRpc`로 재생되며, 로비와 결과 UI 사운드는 각 클라이언트에서 로컬로 재생된다.

또한 로그인/로비 화면에서 사용할 수 있는 종료 버튼 흐름을 공통 유틸로 추가했고, 게임 씬 배경 이미지는 Canvas가 아니라 SpriteRenderer 월드 배경으로 배치해야 한다는 기준도 정리했다.

이번 작업은 기존 MVP 구조를 크게 바꾸지 않고, 사운드와 화면 polish를 붙일 수 있는 최소 기반을 마련한 단계다.
