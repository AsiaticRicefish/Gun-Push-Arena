## 작업 배경

5월 7일 작업에서는 LoginScene 기반의 게스트 로그인, 닉네임 설정, Firestore 유저 데이터 저장 흐름을 구현했다.

다만 당시 `LoginUIController`가 다음 책임을 대부분 직접 가지고 있었다.

```text
버튼 입력 처리
UI 상태 변경
AuthManager 호출
닉네임 검증
로그인 성공 후 씬 이동
```

기능은 동작하지만, 이 상태로 로비와 맵 선택 기능이 붙으면 로그인 UI 코드가 계속 커질 가능성이 있었다.

그래서 5월 11일부터 12일까지는 LoginUI 구조를 MVP 패턴에 가깝게 분리하고, 이후 VContainer 같은 DI 구조로 넘어가기 쉽도록 직접 참조를 줄이는 방향으로 정리했다.

---

## 작업 목표

이번 작업의 목표는 다음과 같았다.

1. LoginUI의 화면 표시 책임과 로그인 흐름 처리 책임을 분리한다.
2. `AuthManager.Instance` 직접 참조를 줄이고 `IAuthService` 인터페이스를 통해 인증 기능을 사용한다.
3. 로그인 성공 후 씬 이동을 UI 코드에서 직접 처리하지 않고 `ISceneLoader`로 분리한다.
4. 로비에서 직접 맵 선택과 랜덤 맵 선택을 할 수 있도록 `MapData`, `IMapSelector`, `MapSelector` 구조를 먼저 준비한다.

단, 로비 UI와 실제 맵 씬은 아직 구현 전이므로 맵 선택 흐름은 실제 연결까지 진행하지 않고 설계와 기본 클래스까지만 준비했다.

---

## LoginUI MVP 구조

LoginUI는 아래처럼 역할을 나누는 방향으로 정리했다.

```text
LoginUIController
→ Unity MonoBehaviour 진입점
→ Inspector 참조 관리
→ 버튼 이벤트를 Presenter로 전달
→ 필요한 의존성 조립

LoginPresenter
→ 로그인 흐름 처리
→ 닉네임 검증
→ AuthService 호출
→ 성공/실패에 따른 View 갱신 요청
→ 로그인 완료 후 씬 이동 요청

LoginUIView
→ 실제 UI 표시 담당
→ 버튼 활성화/비활성화
→ 상태 메시지 표시
→ 닉네임 패널 열기
→ 입력값 제공
```

이 구조로 바꾸면서 `LoginUIController`는 직접 로그인 로직을 처리하지 않고, 버튼 클릭을 `LoginPresenter`에게 넘기는 역할로 줄어들었다.

```csharp
public void OnClickGuestLogin()
{
    _ = presenter.HandleGuestLoginAsync();
}

public void OnClickConfirmNickname()
{
    _ = presenter.HandleConfirmNicknameAsync();
}
```

## AuthManager 직접 참조 줄이기

기존에는 UI 쪽에서 `AuthManager.Instance`를 직접 호출하는 구조였다.

이 방식은 간단하지만, 나중에 VContainer를 도입하거나 테스트용 인증 서비스를 넣고 싶을 때 교체가 어렵다.

그래서 인증 기능을 `IAuthService` 인터페이스로 분리했다.

```csharp
public interface IAuthService
{
    string UserId { get; }
    bool IsLoggedIn { get; }
    UserData CurrentUserData { get; }

    Task<bool> GuestLoginAsync();
    Task<bool> UpdateNicknameAsync(string nickname);
}
```

`AuthManager`는 이 인터페이스를 구현한다.

```csharp
public class AuthManager : GlobalSingleton<AuthManager>, IAuthService
```

현재는 완전한 DI 컨테이너를 사용하지 않지만, `LoginPresenter`는 `AuthManager` 구체 타입이 아니라 `IAuthService`에만 의존한다.

```csharp
private readonly IAuthService authService;
```

이렇게 해두면 나중에 VContainer를 도입했을 때 `IAuthService -> AuthManager` 바인딩으로 자연스럽게 넘어갈 수 있다.

## 씬 전환 책임 분리

5월 7일 구조에서는 로그인 성공 후 UI 코드에서 직접 씬을 이동했다.

```csharp
SceneManager.LoadScene(lobbySceneName);
```

하지만 이후 로딩 화면, 페이드, 비동기 씬 로드, Additive 로드가 들어가면 UI 코드가 다시 복잡해질 수 있다.

그래서 씬 이동 책임을 `ISceneLoader`로 분리했다.

```csharp
public interface ISceneLoader
{
    Task LoadSceneAsync(string sceneName);
}
```

구현체는 `SceneLoader`로 만들었다.

```csharp
public class SceneLoader : MonoBehaviour, ISceneLoader
{
    public async Task LoadSceneAsync(string sceneName)
    {
        if (string.IsNullOrEmpty(sceneName))
        {
            Debug.LogError("[SceneLoader] Scene name is empty.");
            return;
        }

        AsyncOperation operation = SceneManager.LoadSceneAsync(sceneName);

        if (operation == null)
        {
            Debug.LogError($"[SceneLoader] Failed to load scene: {sceneName}");
            return;
        }

        while (!operation.isDone)
        {
            await Task.Yield();
        }
    }
}
```

이후 `LoginPresenter`는 씬 이동을 직접 구현하지 않고 `ISceneLoader`에게 요청한다.

```csharp
private async Task LoadLobbySceneAsync()
{
    await sceneLoader.LoadSceneAsync(lobbySceneName);
}
```

`LoginUIController`는 `SceneLoader`를 Inspector에서 받거나 같은 GameObject에서 찾은 뒤 Presenter에 넘긴다.

```csharp
presenter = new LoginPresenter(view, authService, sceneLoader, lobbySceneName);
```

이제 로그인 UI 코드에는 `SceneManager.LoadScene()` 직접 호출이 남아 있지 않다.

## 맵 선택 구조 준비

로비 구현은 아직 시작하지 않았지만, 이후 로비에서 다음 기능이 필요해질 예정이다.

```text
맵 직접 선택
랜덤 맵 선택
선택한 맵 씬 로드
```

이를 위해 맵 데이터와 맵 선택 책임을 미리 분리했다.

### MapData

맵 정보는 `ScriptableObject`로 관리하는 방향으로 정했다.

```csharp
[CreateAssetMenu(fileName = "MapData", menuName = "Game/MapData")]
public class MapData : ScriptableObject
{
    [SerializeField] private string id;
    [SerializeField] private string mapName;
    [SerializeField] private string sceneName;
    [SerializeField] private Sprite mapImage;

    public string Id => id;
    public string MapName => mapName;
    public string SceneName => sceneName;
    public Sprite MapImage => mapImage;
}
```

필드는 Inspector에서 설정할 수 있도록 `SerializeField private`로 두고, 외부에서는 읽기 전용 프로퍼티로 접근하게 했다.

### IMapSelector

맵 선택 책임은 `IMapSelector`로 분리했다.

```csharp
public interface IMapSelector
{
    MapData[] Maps { get; }

    MapData GetMap(string mapId);
    MapData GetRandomMap();
}
```

### MapSelector

`MapSelector`는 맵 목록을 가지고 있다가 ID로 특정 맵을 찾거나, 랜덤 맵을 반환한다.

```csharp
public class MapSelector : MonoBehaviour, IMapSelector
{
    [SerializeField] private MapData[] maps;

    public MapData[] Maps => maps;

    public MapData GetMap(string mapId)
    {
        foreach (var map in maps)
        {
            if (map.Id == mapId)
            {
                return map;
            }
        }

        Debug.LogWarning($"{mapId}에 해당하는 맵을 찾을 수 없습니다.");
        return null;
    }

    public MapData GetRandomMap()
    {
        if (maps == null || maps.Length == 0)
        {
            Debug.LogWarning("맵 데이터가 없습니다.");
            return null;
        }

        int index = Random.Range(0, maps.Length);
        return maps[index];
    }
}
```

아직 로비 UI가 없기 때문에 실제 사용 흐름은 연결하지 않았다.

## 현재 구조 요약

현재 로그인 관련 구조는 아래와 같다.

```text
LoginUIController
→ LoginPresenter 생성
→ 버튼 이벤트 전달
→ SceneLoader 참조 전달

LoginPresenter
→ IAuthService로 로그인 처리
→ LoginUIView로 UI 갱신
→ ISceneLoader로 LobbyScene 이동 요청

LoginUIView
→ 화면 표시와 입력값 제공

AuthManager
→ IAuthService 구현
→ Firebase Auth / Firestore 유저 데이터 처리

SceneLoader
→ ISceneLoader 구현
→ Unity SceneManager 비동기 씬 로드 담당
```

맵 관련 구조는 아래와 같이 준비되어 있다.

```text
MapData
→ ScriptableObject 맵 데이터
→ id, mapName, sceneName, mapImage 보유

MapSelector
→ IMapSelector 구현
→ 맵 목록 관리
→ ID 기반 맵 찾기
→ 랜덤 맵 선택
```

## 이번 작업에서 정리한 설계 기준

이번 작업에서 정한 기준은 다음과 같다.

```text
UI는 화면 표시와 입력 전달에 집중한다.
로그인 흐름은 Presenter가 담당한다.
Firebase/Auth 구체 구현은 IAuthService 뒤에 숨긴다.
씬 이동은 ISceneLoader 뒤에 숨긴다.
어떤 맵을 고를지는 MapSelector가 담당한다.
선택된 씬을 로드하는 것은 SceneLoader가 담당한다.
```

특히 씬 전환은 로비, 게임, 결과 화면, 랜덤 맵, Additive 로드까지 확장될 수 있으므로 UI 코드에서 직접 처리하지 않는 방향으로 정했다.
