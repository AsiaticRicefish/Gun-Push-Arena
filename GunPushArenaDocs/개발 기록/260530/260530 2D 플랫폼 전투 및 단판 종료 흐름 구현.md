# 2D 플랫폼 전투 MVP 및 맵 프리셋 정리

**날짜:** 2026-05-30  
**작업 기간:** 2026-05-30  

## 작업 요약

오늘 작업으로 `Gun Push Arena`는 로비에서 맵을 선택하고, Relay/Netcode로 게임 씬에 진입한 뒤, 2D 플랫폼 전투를 진행하고, 승패 결과를 표시하는 프로토타입 루프에 가까워졌다.

기존에는 AI 맵 테마가 `Bridge / Island / Warehouse`처럼 시각 테마처럼 보이는 이름이었다. 이번 작업에서는 이를 실제 전투 구조 중심의 프리셋으로 정리했다.

```text
Bridge / Island / Warehouse
-> Balanced / Split / Vertical / Chaos
```

또한 `aiStyleHint` 입력 경로를 제거해서 로비 맵 생성 흐름을 단순화했다. 이제 맵 생성은 사용자의 자유 입력이 아니라 선택한 전투 구조 프리셋을 기준으로 진행된다.

## 맵 프리셋 구조 변경

`AiMapTheme` enum을 전투 구조 중심으로 변경했다.

```csharp
public enum AiMapTheme
{
    Balanced,
    Split,
    Vertical,
    Chaos
}
```

기존 Builder는 새 프리셋 이름에 맞춰 교체했다.

```text
BridgeThemeMapBuilder    -> BalancedMapBuilder
IslandThemeMapBuilder    -> SplitMapBuilder
WarehouseThemeMapBuilder -> VerticalMapBuilder
신규                       ChaosMapBuilder
```

`IntentBasedAiMapBuilder`는 이제 `balanced / split / vertical / chaos` 문자열을 기준으로 Builder를 선택한다. 잘못된 값이 들어오면 `balanced`를 fallback으로 사용한다.

---

## 각 프리셋 의도

### Balanced

기본 대칭형 전투 맵이다. 좌우 스폰이 안정적이고 중앙/상하 보조 플랫폼이 있어 테스트 및 기본 플레이에 적합하다.

### Split

좌우가 분리된 느낌을 주고, 중앙 이동 경로가 제한된 맵이다. 플레이어가 바로 맞붙기보다 이동 선택과 점프 경로가 중요해지도록 설계했다.

### Vertical

상하 높이 차이가 비교적 큰 맵이다. 중앙 장거리 플랫폼과 위/아래 보조 플랫폼을 사용해 고저차 플레이를 유도한다.

### Chaos

작은 플랫폼과 낙사 위험이 많은 맵이다. 다만 검증 실패를 막기 위해 최소 바닥 수를 보강하는 안전 장치를 추가했다.

---

## 맵 검증 실패 보정

`MapValidationSettings.asset`의 `minFloorCount`는 현재 30이다. 일부 프리셋은 플랫폼이 겹치거나 Wall/Danger 적용 후 바닥 수가 줄어들면서 다음 오류로 fallback 기본 맵을 사용했다.

```text
AI 맵 검증에 실패했습니다. 기본 맵을 사용합니다.
Reason: 바닥 타일이 충분하지 않습니다.
```

이를 해결하기 위해 `SplitMapBuilder`, `BalancedMapBuilder`, `ChaosMapBuilder`에 최소 바닥 수 보강 로직을 추가했다.

```text
현재 Floor 수 확인
-> 부족하면 중앙/좌우 보조 플랫폼 추가
-> 스폰 규칙 재보장
```

이 보정은 검증 통과를 위한 최소 안전장치이며, 프리셋의 전투 성격은 유지하도록 했다.

## Ollama AI 맵 요청 정리

`OllamaAiMapClient`의 prompt도 새 프리셋 기준으로 정리했다.

```text
allowed theme:
balanced, split, vertical, chaos
```

기존 `bridgeCount`는 시각 테마 느낌이 강해서 `routeCount`로 변경했다.

```text
bridgeCount -> routeCount
```

또한 `aiStyleHint` 입력 제거에 맞춰 `AiMapGenerateRequest.prompt` 필드도 제거했다. 현재 AI 맵 요청은 선택된 프리셋, 맵 크기, 플레이어 수를 기준으로 동작한다.

## 로비 UI 정리

로비의 맵 선택 드롭다운은 아래 순서로 정리했다.

```text
0 -> Balanced
1 -> Split
2 -> Vertical
3 -> Chaos
```

`LobbyPresenter`와 `LobbyUIView`의 enum/index 매핑도 이 순서에 맞췄다.

`aiStyleHintInput`은 더 이상 코드에서 사용하지 않는다. `LobbyScene.unity`에 남아 있던 기존 입력 오브젝트는 `DeprecatedMapHintInput`으로 이름을 바꾸고 비활성화했다.

Firestore 기존 문서에 `AiStyleHint` 필드가 남아 있어도 현재 코드에서는 읽거나 쓰지 않는다.

## 리스폰 직후 무적 시간

리스폰 직후 바로 다시 맞는 문제를 막기 위해 `PlayerController`에 3초 무적 시간을 추가했다.

```text
리스폰
-> IsInvulnerable = true
-> 3초 동안 투사체 피격 무시
-> 시간이 지나면 IsInvulnerable = false
```

`IsInvulnerable`은 서버가 쓰는 `NetworkVariable<bool>`이다. 클라이언트는 값을 읽어서 무적 상태를 시각적으로 확인할 수 있다.

현재 시각 피드백은 플레이어 색을 원래 색과 흰색 사이로 밝게 보정하는 방식이다.

`NetworkProjectile`은 무적 플레이어와 충돌하면 피격을 적용하지 않고, 투사체도 바로 despawn하지 않도록 수정했다.

## 닉네임 중복 검사 및 실패 안내

닉네임 저장 흐름도 보강했다.

### 닉네임 규칙

```text
길이: 2~12자
저장 전 Trim
중복 기준: Trim 후 소문자 변환
```

`UserData`에는 `NormalizedNickname` 필드를 추가했다.

중복 검사는 Firestore의 예약 컬렉션을 사용한다.

```text
users/{uid}
nicknames/{normalizedNickname}
```

닉네임을 저장할 때는 transaction으로 다음 작업을 함께 처리한다.

```text
현재 user 문서 읽기
-> nicknames/{normalizedNickname} 예약 문서 확인
-> 비어 있거나 본인 소유면 저장
-> 이전 닉네임 예약 문서는 본인 소유일 때만 삭제
```

닉네임 저장 결과는 `NicknameUpdateResult` enum으로 구분한다.

```text
Success
NotLoggedIn
Invalid
Duplicate
Failed
```

로그인 UI에서는 실패 시 상태 텍스트뿐 아니라 별도 안내 패널을 띄우도록 했다.

에디터에서 연결해야 하는 항목은 다음과 같다.

```text
Notice Panel
Notice Message Text
Notice Ok Button
```

닉네임 저장 실패, 중복, 길이 오류가 발생해도 닉네임 패널은 유지되고 확인 버튼도 다시 활성화된다.

Unity Console의 Error Pause로 Play Mode가 멈추는 문제를 막기 위해, 닉네임 저장 실패 로그는 `Debug.LogError`가 아니라 `Debug.LogWarning`으로 처리한다.

## Firestore Rules 주의점

닉네임 중복 검사를 위해 Firestore Rules에 `nicknames` 컬렉션 권한이 필요하다.

필요한 개념은 다음과 같다.

```text
users/{uid}
-> 본인 문서만 읽기/생성/수정

nicknames/{nicknameId}
-> 로그인한 유저는 읽기 가능
-> 생성/수정/삭제는 Uid가 request.auth.uid와 일치할 때만 허용
```

현재는 클라이언트에서 `normalizedNickname` 문서 ID를 생성한다. MVP 단계에서는 충분하지만, 더 강한 보안을 원하면 이후 Cloud Function으로 닉네임 예약 처리를 옮기는 것이 좋다.

## 현재 게임 루프

현재까지의 핵심 플레이 흐름은 다음과 같다.

```text
LoginScene
-> 게스트 로그인
-> 닉네임 설정 및 중복 검사
-> LobbyScene
-> 방 생성/참가
-> 맵 프리셋 선택
-> Host가 맵 생성
-> Firestore FinalMap 저장
-> Relay/Netcode 연결
-> Map1 로드
-> Firestore FinalMap 단건 조회
-> GameMapSpawner가 플랫폼 맵 생성
-> NetworkPlayerSpawner가 플레이어 SpawnAsPlayerObject
-> Owner 입력
-> Server 이동/점프/발사/넉백/낙사 처리
-> 리스폰 시 3초 무적
-> Lives 0이면 탈락
-> 마지막 생존자 승리
-> 결과 UI 표시
-> 로비 복귀
```

## 검증

오늘 작업 후 `dotnet build Assembly-CSharp.csproj`를 실행했다.

빌드는 성공했다.

남아 있는 경고는 기존 `OllamaAiMapClient.OllamaGenerateResponse` 직렬화용 필드 경고 2개다.

```text
OllamaGenerateResponse.response 필드에는 할당되지 않으므로 항상 null 기본값을 사용합니다.
OllamaGenerateResponse.done 필드에는 할당되지 않으므로 항상 false 기본값을 사용합니다.
```

해당 필드는 Unity `JsonUtility` 역직렬화용 필드이므로 현재 동작에는 영향이 없다.

## 남은 작업

프로토타입 마무리를 위해 다음 작업이 남아 있다.

```text
사운드 구조 추가
발사 / 피격 / 점프 / 낙사 / 승리 / 패배 사운드 연결
리스폰 무적 시각 효과 개선
라이프 HUD 표시
카메라 추적
맵 프리셋별 시각 차이 추가
투사체/피격 이펙트 추가
결과 UI와 로비 복귀 흐름 최종 점검
```

현재 기준으로 핵심 멀티플레이 전투 루프는 연결되어 있으므로, 사운드와 폴리싱을 붙이면 프로토타입 완료 단계에 도달할 수 있다.

## 정리

오늘 작업으로 맵 선택 구조, 닉네임 검증, 리스폰 보호, 맵 검증 안정성이 크게 정리되었다.

특히 Firestore는 여전히 로비/방/최종 맵 공유까지 담당하고, 실제 플레이 중 이동/발사/피격/승패는 Netcode 서버 권한으로 처리하는 방향을 유지했다.

이 구조는 이후 사운드, HUD, 카메라, 연출을 얹어도 크게 흔들리지 않는 MVP 기반이 된다.
