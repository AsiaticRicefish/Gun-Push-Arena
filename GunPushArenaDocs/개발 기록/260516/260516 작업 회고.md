## 작업 배경

기존 `RandomMapGenerator`는 전체를 `Empty`로 초기화한 뒤, 맵 내부 대부분을 `Floor`로 채우고 그 위에 `Wall`을 랜덤 배치하는 방식이었다.

이 방식은 넓은 사각형 경기장 위에 장애물이 놓인 형태에 가깝다. 하지만 Gun Push Arena의 핵심 플레이는 총알 넉백으로 상대를 발판 밖으로 밀어 떨어뜨리는 것이므로, 벽보다 발판과 낙사 공간이 더 중요하다.

이번 작업에서는 랜덤 맵 생성 방향을 다음과 같이 바꾸었다.

```text
전체 Empty
-> 중앙 기본 Floor 생성
-> Floor 주변 확장
-> 일부 Floor를 Empty로 깎아 낙사 구멍 생성
-> 스폰 발밑 Floor 보장
-> 스폰 머리 위 공간 보장
```

## RandomMapGenerator 변경

`RandomMapGenerator`는 이제 맵 내부 전체를 바닥으로 채우지 않는다. 중앙에 기본 발판을 만든 뒤, 기존 `Floor` 주변에 새 `Floor`를 랜덤하게 붙여 발판 영역을 확장한다.

현재 생성 흐름은 다음과 같다.

```text
FillEmpty
CreateCenterFloor
ExpandFoor
CreateFallHoles
EnsureSpawnFloor
EnsureSpawnHeadroom
```

### 중앙 발판 생성

`CreateCenterFloor`는 맵 중앙을 기준으로 작은 직사각형 발판을 만든다. 기존 `CreateArenaFloor`처럼 맵 내부 전체를 채우지 않기 때문에, 처음부터 낙사 공간이 남는다.

### Floor 확장

`ExpandFoor`는 랜덤 좌표를 고르고, 해당 칸이 `Empty`이면서 상하좌우 중 하나가 `Floor`일 때 일정 확률로 `Floor`로 바꾼다.

이 방식은 완전히 떨어진 섬을 만들지 않고, 기존 발판에 붙어서 확장되는 구조다.

### 낙사 구멍 생성

`CreateFallHoles`는 이미 생성된 `Floor` 일부를 다시 `Empty`로 바꾼다. 이로 인해 맵 안쪽에도 낙사 위험이 생긴다.

스폰 주변은 `SpawnProtectRadius`로 보호해서 시작 위치 근처가 바로 뚫리는 상황을 줄였다.

### 스폰 보정

기존에는 스폰 주변 3x3을 모두 `Floor`로 만들었다. 이번 작업에서는 이 규칙을 제거하고, 스폰 위치의 발밑 한 칸만 `Floor`로 보장한다.

대신 플레이어 머리 위 공간은 `Empty`로 비워서, 스폰 직후 천장에 막히는 상황을 방지했다.

## MapLayoutValidator 변경

검증기는 기존의 크기, 타일 배열, 스폰, 스폰 간 거리, 최소 바닥 수, 스폰 간 경로 검사를 유지하면서 낙사 중심 맵에 필요한 조건을 추가했다.

현재 추가된 검증 방향은 다음과 같다.

```text
스폰 위치 위쪽이 Empty인지 검사
스폰 주변에 실제로 설 수 있는 Floor가 있는지 검사
Empty 타일 개수가 충분한지 검사
Floor와 Empty가 맞닿는 가장자리 수가 충분한지 검사
Wall 타일이 너무 많지 않은지 검사
```

### 스폰 유효성

`IsSpawnValid`는 이제 스폰 위치가 `Floor`인지뿐 아니라, 스폰 바로 위 칸이 `Empty`인지도 확인한다.

이로 인해 다음과 같은 상황을 실패로 처리할 수 있다.

```text
---F---
---P---
---F---
```

### 설 수 있는 발판 검사

`IsStandableFloor`는 해당 위치가 `Floor`이고, 그 위쪽 공간이 `Empty`인지 검사한다.

`NearbySpawnFloor`는 주변의 아무 `Floor`나 인정하지 않고, `IsStandableFloor`를 통과한 발판만 스폰 주변 이동 후보로 인정한다.

### 낙사 공간 검사

`CountEmptyTiles`는 맵에 `Empty`가 충분한지 확인한다.

`CountFallEdges`는 `Floor`와 `Empty`가 상하좌우로 맞닿아 있는 가장자리 수를 센다. 맵 밖은 세지 않고, 맵 안쪽의 `Empty`만 낙사 공간으로 인정한다.

### Wall 제한

`CountWallTiles`로 `Wall` 개수를 세고, `MapValidationSettings.MaxWallCount`를 넘으면 실패한다. 현재 방향에서는 벽이 중심이 아니므로 벽이 과하게 많은 맵을 막기 위한 장치다.

## MapValidationSettings 변경

낙사 중심 검증을 위해 설정값이 추가되었다.

```text
minEmptyCount
minFallEdgeCount
maxWallCount
```

각 값의 역할은 다음과 같다.

```text
minEmptyCount
낙사 공간으로 볼 Empty 타일의 최소 개수

minFallEdgeCount
Floor와 Empty가 맞닿은 낙사 가능 가장자리의 최소 개수

maxWallCount
벽 중심 맵이 되지 않도록 허용할 최대 Wall 개수
```

## DefaultMapGenerator 변경

Fallback용 기본 맵도 새 검증 기준에 맞게 바꾸었다.

기존 기본 맵은 내부 전체를 `Floor`로 채우고 여러 `Wall`을 배치했기 때문에, 새 검증 기준에서는 스폰 머리 공간이나 `maxWallCount` 조건에 걸릴 수 있었다.

현재 기본 맵 흐름은 다음과 같다.

```text
FillEmpty
CreateDefaultFloor
CreateDefaultFallHoles
CreateDefaultSpawnHeadroom
EnsureSpawnFloor
```

이제 기본 맵도 고정 발판과 내부 낙사 구멍을 가진다. 또한 스폰 발밑은 `Floor`, 스폰 머리 위는 `Empty`로 맞춘다.

## 테스트 확인

현재 별도의 자동화 테스트 코드는 발견되지 않았다. 현재 유효한 테스트 수단은 `MapPreviewSpawner`를 통한 Unity 에디터 내 수동 시각 테스트다.

`MapPreviewSpawner`는 다음 흐름을 확인할 수 있다.

```text
RandomMapGenerator로 맵 생성
MapLayoutValidator로 검증
검증 실패 시 DefaultMapGenerator 사용
Floor, Wall, Spawn marker를 SpriteRenderer로 시각화
```

이번 작업 중 확인한 대표 오류는 다음과 같다.

```text
Random map validation failed.
Reason: 스폰 위치 위쪽 공간이 비어 있지 않습니다.
```

원인은 랜덤 생성기가 스폰 발밑만 보장하고 머리 위 공간을 비우지 않았기 때문이다. 이후 `EnsureSpawnHeadroom`을 추가해 문제가 재현되지 않도록 했다.

## 남은 정리 포인트

현재 기능 흐름은 동작하지만, 다음 정리 포인트가 남아 있다.

```text
RandomMapGenerator에 안 쓰는 using이 남아 있음
PlaceRandomWalls와 WallChance는 현재 호출되지 않음
ExpandFoor는 이름 오타 가능성이 있음
requireSpawnPath는 여전히 Floor를 따라 걷는 경로만 검사함
```

특히 `requireSpawnPath`는 점프가 들어간 뒤에는 너무 엄격한 기준이 될 수 있다. 향후에는 걸어서 연결된 경로 대신, 점프 가능 거리 기준의 도달 가능성 검사로 바꾸는 것이 더 자연스럽다.

다음 작업은 크게 세 갈래로 나눌 수 있다.
