# LoginScene 기반 게스트 로그인 및 닉네임 설정 흐름

**날짜:** 2026-05-07  
**관련 파일:**

- `Assets/Scripts/Core/Data/User/UserData.cs`

## 작업 배경

로비 구현에 들어가기 전에 인증 흐름을 먼저 정리했다.

기존에는 `AuthManager.Start()`에서 Firebase 초기화 직후 익명 로그인을 자동으로 실행했다. 하지만 LoginScene에 Guest 버튼과 이후 Google 로그인 버튼을 둘 예정이므로, 자동 로그인보다 사용자가 버튼을 눌렀을 때 로그인하는 구조가 더 적합하다고 판단했다.

이번 작업의 목표는 다음과 같았다.

1. LoginScene에서 Guest 버튼을 눌러 Firebase 익명 로그인을 실행한다.
2. UID를 기준으로 Firestore `users/{uid}` 문서를 로드하거나 생성한다.
3. 최초 유저라면 닉네임 입력 패널을 연다.
4. 닉네임을 저장하면 Firestore와 `AuthManager.CurrentUserData`를 갱신한다.
5. 닉네임 설정이 끝난 유저는 이후 로그인 시 바로 LobbyScene으로 이동한다.

Netcode는 아직 시작하지 않는다. 로그인 씬은 Firebase Auth와 Firestore 유저 데이터까지만 담당하고, Netcode는 로비에서 방 만들기 또는 참가 시점에 시작하는 방향으로 정했다.

---

## 최종 흐름

현재 로그인 흐름은 아래 순서로 진행된다.

```text
LoginScene 시작
→ FirebaseManager 초기화
→ AuthManager 초기화
→ Guest 버튼 클릭
→ Firebase 익명 로그인
→ UID 확보
→ Firestore users/{uid} 로드 또는 생성
→ IsNicknameSet 확인
→ true: LobbyScene 이동
→ false: 닉네임 입력 패널 표시
→ 닉네임 저장
→ LobbyScene 이동
```

## AuthManager 변경 사항

### 자동 익명 로그인 제거

기존에는 `Start()`에서 바로 익명 로그인을 실행했다.

```csharp
private async void Start()
{
    await WaitForFirebase();
    InitAuth();
    await SignInAnonymously();
}
```

버튼 로그인 방식으로 바꾸기 위해 익명 로그인 호출을 제거했다.

```csharp
private async void Start()
{
    await WaitForFirebase();
    InitAuth();
    // await SignInAnonymously();
}
```

이제 `Start()`는 Firebase/Auth 준비까지만 담당한다.

### GuestLoginAsync 추가

UI에서 직접 `SignInAnonymously()`를 호출하지 않도록 public 래퍼를 추가했다.

```csharp
public async Task<bool> GuestLoginAsync()
{
    await SignInAnonymously();
    return IsLoggedIn && CurrentUserData != null;
}
```

`SignInAnonymously()`는 Firebase 익명 로그인이라는 내부 구현이므로 `private`으로 유지했다.

### UpdateNicknameAsync 추가

현재 로그인된 유저 기준으로 닉네임을 저장하는 메서드를 추가했다.

```csharp
public async Task<bool> UpdateNicknameAsync(string nickname)
{
    if (!IsLoggedIn || CurrentUserData == null)
    {
        Debug.LogError("[Auth] Cannot update nickname before login.");
        return false;
    }

    bool success = await userDataService.UpdateNicknameAsync(UserId, nickname);
    if (!success)
    {
        return false;
    }

    CurrentUserData.Nickname = nickname;
    CurrentUserData.IsNicknameSet = true;
    CurrentUserData.UpdatedAt = Firebase.Firestore.Timestamp.GetCurrentTimestamp();

    Debug.Log($"[Auth] CurrentUserData nickname updated: {nickname}");
    return true;
}
```

UI는 UID나 Firestore 접근 방식을 몰라도 되고, `AuthManager`만 호출하면 된다.

## UserData 변경 사항

닉네임이 유저가 직접 설정한 값인지 판단하기 위해 `IsNicknameSet` 필드를 추가했다.

```csharp
[FirestoreProperty] public bool IsNicknameSet { get; set; }
```

기본 닉네임은 여전히 `Player_xxxx` 형태로 생성한다. 다만 새 유저 생성 시에는 `IsNicknameSet = false`로 저장한다.

```csharp
UserData newUser = new UserData
{
    Uid = uid,
    Nickname = CreateDefaultNickname(uid),
    ColorHex = CreateDefaultColorHex(uid),
    IsNicknameSet = false,
    CreatedAt = Timestamp.GetCurrentTimestamp(),
    UpdatedAt = Timestamp.GetCurrentTimestamp()
};
```

이렇게 하면 기본 닉네임이 있어도 최초 닉네임 설정 화면을 보여줄 수 있다.

## UserDataService 변경 사항

Firestore 유저 문서에 닉네임을 저장하는 메서드를 추가했다.

```csharp
public async Task<bool> UpdateNicknameAsync(string uid, string nickname)
{
    try
    {
        DocumentReference docRef = firestore.Collection("users").Document(uid);

        Dictionary<string, object> updates = new Dictionary<string, object>
        {
            { "Nickname", nickname },
            { "IsNicknameSet", true },
            { "UpdatedAt", Timestamp.GetCurrentTimestamp() }
        };

        await docRef.UpdateAsync(updates);
        Debug.Log($"[UserDataService] Nickname updated: {nickname}");
        return true;
    }
    catch (System.Exception e)
    {
        Debug.LogError($"[UserDataService] Error updating nickname: {e}");
        return false;
    }
}
```

Firestore 업데이트 성공 여부를 `bool`로 반환하도록 해서 UI 흐름에서 성공/실패를 판단할 수 있게 했다.

## LoginUIController 변경 사항

`LoginUIController`는 LoginScene의 UI 흐름만 담당한다.

주요 참조는 다음과 같다.

- Guest 로그인 버튼
- 닉네임 입력 패널
- 닉네임 입력 필드
- 닉네임 확인 버튼
- 상태 텍스트
- 로비 씬 이름

Guest 버튼 클릭 시:

```text
버튼 비활성화
→ Signing in... 표시
→ AuthManager.Instance.GuestLoginAsync()
→ 성공 시 IsNicknameSet 확인
→ true면 LobbyScene 이동
→ false면 닉네임 패널 표시
```

닉네임 확인 버튼 클릭 시:

```text
입력값 Trim
→ 2-12자 검사
→ 저장 버튼 비활성화
→ AuthManager.Instance.UpdateNicknameAsync(nickname)
→ 성공하면 LobbyScene 이동
→ 실패하면 버튼 재활성화
```

닉네임 입력 규칙은 현재 단순하게 유지했다.

```text
최소 2자
최대 12자
앞뒤 공백 제거
```

중복 닉네임 검사는 아직 적용하지 않았다.

## Singleton 및 씬 배치

`GlobalSingleton<T>`는 인스턴스를 유지하기 위해 `DontDestroyOnLoad(gameObject)`를 사용한다.

```csharp
Instance = this as T;
DontDestroyOnLoad(gameObject);
```

따라서 `FirebaseManager`와 `AuthManager`는 LoginScene에만 배치하고, LobbyScene에서는 제거하는 방향이 맞다.

현재 권장 씬 구성은 다음과 같다.

```text
LoginScene
- FirebaseManager
- AuthManager
- LoginUIController

LobbyScene
- Lobby UI
- FirebaseManager 없음
- AuthManager 없음
```

LobbyScene에 같은 싱글톤 오브젝트를 다시 배치하면 중복 생성 후 파괴되거나, 초기화 순서가 헷갈릴 수 있다.

## 작업 중 확인한 이슈 및 정리

### 1. 자동 로그인 호출이 남아있는지 확인 필요

처음 구조에서는 `AuthManager.Start()`에서 `SignInAnonymously()`를 자동 호출했다. 버튼 로그인 구조에서는 이 호출이 남아 있으면 Guest 버튼을 누르기 전에 이미 로그인되어 버린다.

현재는 주석 처리되어 있다.

```csharp
// await SignInAnonymously();
```

### 2. 파일 저장 타이밍 혼동

작업 중 IDE에서는 주석 처리된 것으로 보였지만, 터미널에서 읽은 내용에는 호출이 살아있는 것처럼 보인 순간이 있었다.

원인은 저장 타이밍 차이로 추정된다. 이후 다시 확인했을 때 디스크에 저장된 파일에는 정상적으로 주석 처리되어 있었다.

교훈:

```text
Unity/IDE에서 수정 후 테스트 전 저장 여부를 확인한다.
의심될 때는 파일 내용을 다시 읽어 실제 저장 상태를 확인한다.
```

### 3. 기존 Firestore 문서의 IsNicknameSet 기본값

`IsNicknameSet` 필드 추가 이전에 만들어진 유저 문서는 해당 필드가 없을 수 있다. 이 경우 Firestore 변환 시 `false`처럼 동작할 수 있다.

따라서 기존 테스트 유저는 닉네임이 이미 있어도 한 번 더 닉네임 설정 패널이 뜰 수 있다. 저장하면 `IsNicknameSet = true`가 기록되므로 이후부터는 바로 로비로 이동한다.

### 4. Firebase 경고 로그

테스트 중 아래 로그가 출력되었다.

```text
Database URL not set in the Firebase config.
USE_AUTH_EMULATOR not set.
```

현재 프로젝트는 Realtime Database와 Auth Emulator를 사용하지 않으므로 이번 로그인/Firestore 흐름에는 문제가 되지 않았다.

### 5. LoginScene에서는 Netcode를 시작하지 않음

로그인과 유저 데이터 저장은 Firebase 영역이다.

LoginScene에서는 아래 호출을 하지 않는다.

```text
NetworkManager.StartHost()
NetworkManager.StartClient()
NetworkManager.StartServer()
```

Netcode는 LobbyScene에서 방 만들기, 초대코드 참가, 자동 매칭 단계에 들어갈 때 시작한다.

## 현재 상태

- Guest 버튼으로 Firebase 익명 로그인을 실행할 수 있다.
- UID 기준으로 Firestore `users/{uid}` 문서를 로드하거나 생성한다.
- 새 유저는 기본 닉네임과 색상을 가진다.
- `IsNicknameSet`으로 최초 닉네임 설정 여부를 판단한다.
- 닉네임을 입력해 Firestore에 저장할 수 있다.
- 저장된 닉네임은 `AuthManager.CurrentUserData`에도 반영된다.
- 닉네임 설정이 끝난 유저는 다음 로그인부터 바로 LobbyScene으로 이동한다.
- `FirebaseManager`, `AuthManager`는 LoginScene에서 생성되고 씬 이동 후에도 유지된다.

## 검증 방법

1. LoginScene을 실행한다.
2. Guest 버튼을 누른다.
3. 신규 유저라면 닉네임 패널이 열리는지 확인한다.
4. 닉네임을 입력하고 확인 버튼을 누른다.
5. Console에서 아래 로그를 확인한다.

```text
[UserDataService] Nickname updated: ...
[Auth] CurrentUserData nickname updated: ...
```

6. LobbyScene으로 이동하는지 확인한다.
7. 다시 실행 후 같은 유저 세션에서 Guest 버튼을 누른다.
8. `IsNicknameSet == true`라면 닉네임 패널 없이 바로 LobbyScene으로 이동하는지 확인한다.
