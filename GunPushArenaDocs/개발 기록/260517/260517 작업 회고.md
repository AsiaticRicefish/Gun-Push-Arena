## 작업 배경

이전 작업에서 `RandomMapGenerator`와 `DefaultMapGenerator`를 발판/낙사 중심 구조로 바꾸고, `MapLayoutValidator`에 낙사 공간, 낙사 가장자리, 스폰 머리 공간, Wall 개수 제한 검증을 추가했다.

이번 작업에서는 이 검증 구조 위에 AI 맵 생성 파이프라인을 올리기 위한 기초 작업을 진행했다.

처음에는 ChatGPT나 Claude API가 단순히 랜덤 맵을 생성하는 용도라면 기존 코드 랜덤 생성기와 차별점이 크지 않다고 판단했다. 대신 멀티 게임의 방장이 프롬프트를 입력하고, 그 프롬프트에 맞는 맵을 생성하는 방향이 더 의미 있다고 정리했다.

최종 목표 흐름은 다음과 같다.

```text
방장 프롬프트 입력
-> Unity가 Firebase Function 호출
-> Firebase Function이 OpenAI/Claude API 호출
-> AI가 맵 JSON 생성
-> Unity가 DTO를 MapLayoutData로 변환
-> MapLayoutValidator로 검증
-> 성공한 맵을 모든 클라이언트가 같은 데이터로 사용
```

이번 작업에서는 실제 Firebase/API 연결 전, Unity 내부에서 AI 응답 파싱과 검증 흐름을 테스트할 수 있도록 Fake AI 클라이언트를 만들었다.

## IMapGenerator 정리

기존 `RandomMapGenerator`와 `DefaultMapGenerator`, 이후 추가될 `AiMapGenerator`를 같은 방식으로 다루기 위해 `IMapGenerator`를 추가했다.

```csharp
public interface IMapGenerator
{
    MapLayoutData Generate();
}
```

이 인터페이스의 목적은 다음과 같다.

```text
랜덤 생성기
기본 fallback 생성기
AI 생성기
```

를 모두 `MapLayoutData Generate()` 규칙으로 통일하는 것이다.

이를 통해 `MapPreviewSpawner`나 이후 실제 게임 흐름에서 생성 방식이 바뀌어도 호출부는 `IMapGenerator`만 알면 되도록 만들었다.

## AI 맵 DTO 구조

AI/Firebase 응답을 바로 `MapLayoutData`로 받지 않고, 중간 데이터 구조인 DTO를 만들었다.

DTO는 Data Transfer Object의 줄임말이며, 이 작업에서는 JSON 데이터를 주고받기 위한 단순 데이터 상자 역할을 한다.

현재 구조는 다음과 같다.

```text
AiMapGenerateRequest
Unity가 Firebase Function에 보낼 요청 데이터

AiMapGenerateResponse
Firebase Function 또는 FakeAiMapClient가 Unity에 돌려줄 응답 데이터

AiMapLayoutDto
AI가 생성한 맵 데이터 본문

AiVector2IntDto
JSON에서 좌표를 주고받기 위한 x/y 데이터
```

### AiMapGenerateRequest

방장 프롬프트와 맵 생성 조건을 담는다.

```text
roomId
prompt
width
height
playerCount
```

향후 Firebase Function을 호출할 때 이 데이터가 요청 본문이 될 예정이다.

### AiMapGenerateResponse

AI 맵 생성 결과를 담는다.

```text
success
map
errorMessage
```

성공 시 `map`에 `AiMapLayoutDto`가 들어가고, 실패 시 `errorMessage`로 실패 이유를 전달한다.

### AiMapLayoutDto

실제 맵 데이터를 JSON 친화적인 형태로 담는다.

```text
width
height
tiles
player1Spawn
player2Spawn
```

`tiles`는 `int[]`이며, 타일 값은 다음 규칙을 따른다.

```text
0 = Empty
1 = Floor
2 = Wall
```

### AiVector2IntDto

`Vector2Int`를 JSON에서 단순히 표현하기 위한 좌표 DTO다.

```text
x
y
```

## AiMapLayoutParser

`AiMapLayoutParser`는 AI/Firebase에서 받은 DTO를 실제 게임 내부에서 사용하는 `MapLayoutData`로 변환한다.

현재 핵심 메서드는 다음과 같다.

```text
ToMapLayoutData(AiMapLayoutDto dto, out MapLayoutData layout, out string errorMessage)
```

이 메서드는 다음을 검사한다.

```text
dto가 null인지
tiles 배열이 null인지
tiles 길이가 width * height와 일치하는지
player1Spawn / player2Spawn이 null인지
tile 값이 0, 1, 2 범위 안인지
```

검사에 성공하면 `int[]` 타일 배열을 `MapTileType[]`로 변환하고, `MapLayoutData`를 생성한다.

이 Parser의 역할은 `MapLayoutValidator`와 다르다.

```text
AiMapLayoutParser
JSON/DTO가 MapLayoutData로 변환 가능한 기본 형태인지 검사

MapLayoutValidator
게임 규칙상 플레이 가능한 맵인지 검사
```

따라서 AI 응답은 다음 두 단계를 모두 통과해야 실제 맵으로 사용된다.

```text
DTO 변환 검사
-> 게임 규칙 검증
```

## IAiMapClient

AI 맵 응답을 받아오는 공통 인터페이스를 추가했다.

```csharp
public interface IAiMapClient
{
    AiMapGenerateResponse GenerateMap(AiMapGenerateRequest request);
}
```

현재는 `FakeAiMapClient`가 이 인터페이스를 구현한다.

향후 실제 API 연결 시에는 같은 인터페이스를 구현하는 `FirebaseAiMapClient`를 추가할 예정이다.

```text
FakeAiMapClient
개발/테스트용 가짜 AI 응답

FirebaseAiMapClient
Firebase Function을 호출하는 실제 AI 맵 클라이언트
```

이렇게 분리한 이유는, AI 맵 생성 흐름의 나머지 코드를 바꾸지 않고 클라이언트 구현만 교체하기 위해서다.

## AiMapGenerator

`AiMapGenerator`는 AI 응답을 실제 `MapLayoutData`로 바꾸는 맵 생성기다.

현재 흐름은 다음과 같다.

```text
IAiMapClient.GenerateMap(request)
-> AiMapGenerateResponse 확인
-> AiMapLayoutParser.ToMapLayoutData
-> MapLayoutValidator.Validate
-> 실패 시 DefaultMapGenerator 사용
-> 성공 시 AI 맵 반환
```

실패 처리는 다음 경우에 fallback으로 이어진다.

```text
AI 응답이 null인 경우
response.success가 false인 경우
DTO를 MapLayoutData로 변환하지 못한 경우
MapLayoutValidator 검증에 실패한 경우
```

이 구조 덕분에 AI 응답이 불안정하더라도 게임은 `DefaultMapGenerator`로 안전하게 대체할 수 있다.

## FakeAiMapClient

실제 Firebase/API 연결 전, Unity 내부에서 AI 맵 생성 파이프라인을 테스트하기 위해 `FakeAiMapClient`를 만들었다.

`FakeAiMapClient`는 `AiMapGenerateRequest.prompt` 값을 보고 고정 샘플 맵을 반환한다.

현재 분기 규칙은 다음과 같다.

```text
prompt에 "bridge" 포함
-> CreateBridgeMap()

prompt에 "island" 포함
-> CreateIslandMap()

그 외
-> CreateDefaultSampleMap()
```

### bridge 샘플

`bridge` 샘플은 좌우 섬과 중앙 다리 구조를 가진다.

```text
좌측 큰 발판
우측 큰 발판
중앙 좁은 다리
내부 Empty 구멍
스폰 머리 위 Empty
```

처음에는 중앙 다리형 맵의 Floor 개수가 부족해 `minFloorCount` 검증에 실패했다. 이후 좌우 섬을 넓히고 중앙 연결부를 보강해 검증을 통과하도록 수정했다.

### island 샘플

`island` 샘플은 좌우 섬과 작은 중앙 섬을 가진다.

```text
좌측 섬
우측 섬
중앙 작은 섬
일부 연결 발판
낙사 구멍
스폰 머리 위 Empty
```

이 샘플을 통해 프롬프트 변경에 따라 서로 다른 맵이 반환되는지 확인했다.

## MapPreviewSpawner 변경

`MapPreviewSpawner`에 미리보기 생성 소스를 선택하는 enum을 추가했다.

```text
Random
FakeAi
Default
```

또한 AI 미리보기용 prompt 입력 필드를 추가했다.

```text
aiPrompt
```

현재 Inspector에서 `previewMapSource`를 `FakeAi`로 설정하고, `aiPrompt`를 `bridge` 또는 `island`로 바꾸면 서로 다른 Fake AI 맵을 확인할 수 있다.

미리보기 흐름은 다음과 같다.

```text
PreviewMapSource.FakeAi 선택
-> AiMapGenerateRequest 생성
-> FakeAiMapClient 생성
-> AiMapGenerator 생성
-> Generate()
-> 기존 SpawnTiles / SpawnMarker로 시각화
```

## 확인한 내용

이번 작업에서 확인한 내용은 다음과 같다.

```text
FakeAiMapClient가 prompt에 따라 다른 DTO를 반환한다.
AiMapLayoutParser가 DTO를 MapLayoutData로 변환한다.
AiMapGenerator가 Validator를 통해 검증한다.
검증 성공 시 Default fallback 없이 AI 맵이 표시된다.
bridge / island 샘플 모두 MapPreviewSpawner에서 오류 없이 표시된다.
```

`bridge` 샘플은 처음에 Floor 개수가 부족해 다음 오류가 발생했다.

```text
AI 맵 검증에 실패했습니다.
Reason: 바닥 타일이 충분하지 않습니다.
```

이후 `CreateBridgeMap`의 좌우 섬과 연결부를 넓혀 검증을 통과하도록 수정했다.

## 현재 한계

현재 AI 맵 생성은 실제 API를 호출하지 않는다.

```text
OpenAI/Claude API 연결 없음
Firebase Function 연결 없음
Firestore/Realtime Database 저장 없음
멀티 동기화 없음
```

현재 단계는 어디까지나 다음을 확인하기 위한 기초 파이프라인이다.

```text
AI 응답 모양의 데이터
-> Unity DTO
-> MapLayoutData
-> Validator
-> Preview
```

또한 현재 `IAiMapClient.GenerateMap`은 동기 메서드다. 실제 Firebase Function 호출은 네트워크 작업이므로 향후 비동기 구조로 바뀔 가능성이 높다.

```text
현재
GenerateMap(request)

향후 가능성
GenerateMapAsync(request)
```

다음 작업은 실제 Firebase 연결 설계다.

우선 설계해야 할 것은 다음과 같다.

```text
FirebaseAiMapClient 역할 정의

Firebase Function -> OpenAI/Claude API 호출 구조
AI 응답 JSON 정리
Firestore 또는 Realtime Database 저장 위치
방장만 생성 요청 가능하도록 제한
요금 폭주 방지를 위한 쿨타임/횟수 제한
```

권장 구조는 다음과 같다.

```text
Unity Client
-> Firebase Cloud Functions
-> OpenAI/Claude API
-> AiMapGenerateResponse
-> Unity Parser/Validator
-> 검증된 맵을 방 데이터로 공유
```

멀티 게임에서는 각 클라이언트가 따로 AI 맵을 생성하면 안 된다. 방장 또는 서버가 한 번 생성한 맵 데이터를 모든 클라이언트가 동일하게 받아야 한다.

다음 채팅/작업에서는 다음 주제로 바로 이어갈 수 있다.

```text
FirebaseAiMapClient 설계

Firestore/Realtime Database 맵 저장 구조 설계

```
